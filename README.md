# 可变快照目录的成套制品资料领取

按业务坐标领取厂商元数据并保存原文，不把可变快照名当成不可变文件身份。一组坐标对应的主文件、指定分类附件和来源元数据作为一套接收，只装同一次构建，并能说明最终用了哪一次发布。

## 运行

使用 Node.js 22。依赖版本已锁定，运行、测试和演示不下载任何数据或软件。运行时只使用 Node.js 内置模块。

- `npm test`：执行本地来源交互及收件存储测试。
- `npm run build`：逐个检查模块语法。
- `npm run demo`：启动本地来源，运行当前领取流程，打印真实收件结果后退出。
- `npm start`：在 127.0.0.1:8080 启动本地来源，PORT 可调整。`GET /health` 返回服务与当前来源版本；原有 `/_health` 仍可使用。

容器方式：`docker build -t collection-maven .`，然后 `docker run --rm --network none collection-maven`。镜像构建属于环境准备，运行时不访问公网。

## 领取语义

`receiveCurrent(base, directory)` 按领取单接收整套资料：主文件、必需与可选分类附件，以及来源元数据（领取单与 maven-metadata.xml 原文）一并收存。结果中 `release` 说明最终用的是哪一次发布（具体时间戳构建），`build` 是当前锁定的构建，`files` 逐个列出状态。

同一套资料只装同一次构建：若快照元数据把不同附件指向不同构建，本次不领取任何文件，保留不齐状态（`cohort.consistent=false`，可重试），等目录齐整后再领。文件状态区分 `received`、`absent`（404，此次具体地址确实不存在）与 `retryable`（503、校验不符、网络异常等，可再次领取）；可选附件缺失只记为 `absent`，不影响必需文件已收进度。

每个坐标的进度持久化在 `directory/sets/`，逐文件原子落盘。再次执行只补未完成的文件，已收文件不重复下载；厂商发布新构建时整组切换到新构建，旧构建进度留在 `previous` 中备查，绝不把两次构建凑成一套。

## 项目结构

`src/domain.mjs` 提供当前业务读取入口；`src/metadata.mjs` 解析领取单与快照元数据并判定同一次构建；`src/sets.mjs` 持久化成套领取进度；`src/client.mjs` 负责人工指定地址的有限大小原始领取；`src/archive.mjs` 保存内容及来源凭据。`provider/` 是独立的本地来源服务，`docs/source-contract.md` 说明它的资料和状态约定。演示使用临时目录，正式接入可向业务入口传入持久目录。

本地服务中的机构、记录和文件都是合成业务资料，不使用真实账号、个人信息或第三方站点数据。当前演示通常十秒内结束，全部本地测试应在六十秒内结束。
